Today in one slide

The MCP server holds the rules; n8n runs the steps around it

MCP

  • A server is an interface for an agent, not a wrapper around a REST API.
  • Tool descriptions and error messages are prompts: they steer the agent.
  • A forbidden transition is refused in server code, whatever the agent asks.
  • The protocol changed on 28 July 2026: check anything written before it.

n8n

  • Sits between closed SaaS and your own code: a visual flow, code where needed, self-hosted.
  • Steps you can name go into the workflow; an LLM only where you can't name them.
  • Guarantees come from nodes: a JSON check, an IF rule, an approval step.
  • Has limits: the licence, Git, load, tools per agent.
In practiceIn the homework: the transition rule goes in the server, a JSON check after each agent, and the expected outcome written down before every run.
